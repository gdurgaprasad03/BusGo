# Deploying the BusGo backend on Render (about 45 minutes, free)

You need three free accounts: **GitHub** (you have it), **Render** (you have it), a **MySQL host** (Aiven, below) and an **email
service** (Brevo, below). The code and settings are already prepared in this repository (`render.yaml`, `backend/Dockerfile`).

## Why these choices

| Need | Choice | Reason |
|---|---|---|
| Run the Spring Boot app | **Render** web service (Docker) | deploys straight from GitHub |
| MySQL database | **Aiven free MySQL** (or any MySQL, e.g. TiDB Cloud) | Render has no MySQL; its own database is PostgreSQL only |
| Send email | **Brevo** over HTTPS | Render's free plan blocks SMTP ports (25, 465, 587), so Gmail SMTP cannot work there |

Limits of the free setup (be aware): Render's free web service **sleeps after 15 minutes without traffic** and takes about a minute
to wake; free databases have size and activity limits (check each provider's current terms). For a permanent, always-on service use a
paid plan.

## Step 1: MySQL on Aiven

1. Sign up at https://aiven.io and create a **MySQL** service on the **Free** plan.
2. When it is running, open the service **Overview**. Note: host, port, user (usually `avnadmin`), password and database name
   (usually `defaultdb`). Aiven requires TLS.
3. Build the three values Render will need:
   * `DB_URL` = `jdbc:mysql://HOST:PORT/DATABASE?sslMode=REQUIRED&serverTimezone=UTC&rewriteBatchedStatements=true`
   * `DB_USERNAME` = the user
   * `DB_PASSWORD` = the password
4. The app creates all its tables itself (Flyway) the first time it starts. You do not create tables by hand.

## Step 2: Email on Brevo

1. Sign up at https://www.brevo.com (free plan).
2. **Senders, Domains & Dedicated IPs > Senders > Add a sender.** Use an email address you own (your Gmail is fine) and click the
   verification link Brevo sends to it. Only verified senders can send.
3. **SMTP & API > API keys > Generate a new API key.** Copy it (shown once). This is the `BREVO_API_KEY`.
4. `MAIL_FROM` = `BusGo <the-verified-sender-address>`.
5. Brevo may review new accounts before allowing transactional email. If emails are refused, check the Brevo dashboard.

## Step 3: Deploy on Render

1. Push the repository to GitHub (the files `render.yaml` and `backend/Dockerfile` must be on GitHub).
2. In Render: **New > Blueprint**, pick the `gdurgaprasad03/BusGo` repository, and continue. Render reads `render.yaml`.
3. Render asks for the values marked `sync:false`. Enter them in the Render page (never in GitHub):
   `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `BREVO_API_KEY`, `MAIL_FROM`, and leave `GOOGLE_CLIENT_IDS` empty for now.
   (`JWT_SECRET` is generated by Render.)
4. Click **Apply**. The first build takes several minutes.
5. When it says **Live**, open `https://<your-service>.onrender.com/api/health`. You should see `"status":"UP"`
   (after a wake-up delay if the service was idle).
6. `https://<your-service>.onrender.com/api/auth/config` should show `"emailEnabled":true`.

**Creating the service by hand instead of the Blueprint** (the "New > Web Service" form):

| Field | Value |
|---|---|
| Language | `Docker` |
| Branch | `main` |
| Root Directory | **leave empty** |
| Dockerfile Path | `./Dockerfile` (the default; the file is at the top of the repository) |
| Docker build context | the default (`.`) |
| Instance type | `Free` |
| Health Check Path (Advanced) | `/api/health` |

Do not set Root Directory to `backend` and do not pick a folder in the Dockerfile Path dropdown: the Dockerfile copies from the
`backend/` folder itself, so it must be built from the repository root. (An earlier version of this guide said otherwise and failed with
`COPY .mvn ... not found`.)
**First start:** the app creates about 10,000 demo trips in the background. Over a remote database this can take several minutes;
searches show fewer buses until the log line `Demo data check complete` appears (Render > Logs). If the service runs out of
memory on the free plan, add the variable `APP_DEMO_INCLUDE_GENERATED_ROUTES` = `false` (about a third of the data) or move to a larger plan.

## Step 4: Build the phone app for the hosted server

Use your real Render address (it is shown at the top of the service page):
```powershell
cd frontend
flutter build apk --release --dart-define=API_BASE_URL=https://YOUR-SERVICE.onrender.com --dart-define=API_TIMEOUT_SECONDS=90
```
The result is `frontend\build\app\outputs\flutter-apk\app-release.apk`. HTTPS works in release builds, and the 90-second wait covers the
wake-up delay (the app then shows "the server may be waking up" instead of a plain error).

## Step 5: Check it end to end

1. Open the app: register a new account. A **Welcome to BusGo** email should arrive.
2. Login > **Forgot Password?** > the code email arrives > reset works.
3. Search a route, book, and check the confirmation email.
4. If something fails, open Render > **Logs**. Lines like `Brevo refused the email ... HTTP 401` mean the API key or sender is wrong.

## Security notes

* Secrets live only in the Render dashboard. The repository contains none (`application-local.properties` is git-ignored).
* The demo-reset endpoint is off by default (`app.demo.reset-enabled=false`). Never turn it on for a public server.
* `FORWARD_HEADERS_STRATEGY=native` makes the app use the real client address behind Render's proxy, so the login limit (10 per minute per
  client) applies per user, not to everyone at once. Only enable it behind a proxy.
* This is still a demo: bus data is fictional, payment is simulated, and accounts are not email-verified. Anyone on the internet can
  register, so do not store real personal data.
* If the Gmail app password was pasted into a chat, revoke it. The hosted setup does not use Gmail at all.

## What has and has not been tested

Tested here: the packaged jar starts using only environment variables (database, port, secrets, Brevo provider), honours `PORT`, enables
the Brevo sender, and rate-limits per forwarded client; the Brevo request format is tested against a local stand-in server.
**Not tested here:** the Docker image itself (Docker is not installed on this PC), the real Render build, a real Aiven database, and a real
Brevo email. Expect to fix small first-deploy issues; send me the Render log if anything fails.
